### 1.2 기본 모델: Gemini 3.1 Flash-Lite 유지

1. **비용 구조가 출력 지배적**(한국어 출력 토큰 > 영어 입력 토큰). 출력 $1.50은 Haiku 4.5의 30%, Sonnet 5의 10%.
2. **무료 티어**: Google AI Studio는 Flash 계열에 일일 무료 할당 — 모드 1~2개 번역은 사용자 비용 0원인 경우가 많음. "자기 키를 넣는" UX에서 진입장벽 최저.
3. **작업 난이도가 낮아짐**: 선별 규칙이 어려운 판단을 이미 걸렀고, 용어집이 도메인 어휘를 고정. 남는 건 짧은 문장 EN→KO + 토큰 보존.
4. **구조화 출력**: `response_schema`로 스키마 강제 → 소형 모델 최대 실패 모드(포맷 붕괴)를 API 레벨에서 제거.
5. 2.5 Flash-Lite 은퇴로 더 싼 선택지가 실질적으로 없음.

리스크(긴 문장 자연스러움, 토큰 보존 정확도)는 모델 선택이 아니라 검증 루프 + 에스컬레이션으로 흡수(§4). 실패율 3~8% 예상, 에스컬레이션 비용은 전체의 5% 미만.

### 1.3 복수 공급자: "프로토콜만 정의, 구현은 하나"

필요한 이유 — DB가 변형(variant) 다중화 구조이고 `pack.json`에 모델명을 기록해 사용자가 비교/선택한다. 서로 다른 모델의 번역 공존이 설계 의도. 또 사용자가 Claude/OpenAI 키만 가진 경우가 흔함.

범위를 줄여야 하는 이유 — 공급자마다 SDK·구조화 출력·레이트리밋 헤더·에러 분류가 다름. 3개 동시 유지는 검증 안 된 경로 2개를 낳는다.

```python
class TranslationProvider(Protocol):
    name: str            # variant 메타에 기록 (예: "gemini-3.1-flash-lite")
    price_in: float      # per 1M
    price_out: float
    async def translate(self, system: str, payload: str) -> ProviderResult: ...
    # ProviderResult = {items: [{i:int, ko:str}], in_tok:int, out_tok:int}
```

- **v1**: `GeminiProvider`만. **v1.1**: `AnthropicProvider`(Haiku 4.5) 옵션 의존성. **보류**: OpenAI.
- **`cost.py` 리팩터링 필수**: 단가가 모듈 상수 → `CostTracker(price_in, price_out)` 주입으로 변경, 잡 매니페스트에 단가 기록.

### 1.4 대표 시나리오별 예상 비용

산정 가정: 키당 입력 = 원문 40 tok + 키 이름 12 + JSON 오버헤드 8 = 60 tok / 요청당 공유 컨텍스트 2,000 tok ÷ 40키 = 키당 50 tok → **키당 입력 110 tok**, **키당 출력 75 tok**, 재시도 오버헤드 ×1.15.

| 시나리오 | 대상 키 | 3.1 Flash-Lite | 3 Flash | Haiku 4.5 | Sonnet 5 |
|---|---:|---:|---:|---:|---:|
| A. 스톡 Squad (대상 ~8,500) | 8,500 | **$1.37** | $2.74 | $4.75 | $14.2 |
| B. 대형 모드 | 2,000 | **$0.32** | $0.64 | $1.12 | $3.35 |
| C. 중형 모드 | 400 | **$0.06** | $0.13 | $0.22 | $0.67 |
| D. 설치본 전체 (200개 × 평균 300키) | 60,000 | **$9.7** | $19.3 | $33.5 | $100 |

추가 절감: 프롬프트 캐싱(~15% 절감), 배치 API 50%(D $9.7 → $4.9, 최대 24시간 소요 — "전체 번역" 옵션으로만 제공), 무료 티어(B/C는 대개 무료 할당 내).

→ 비용은 채택 장벽이 아님. "가장 싼 모델"이 아니라 "충분히 싸면서 실패율이 낮은 모델"이 기준.

## 2. 배치 / 병렬 전략

### 2.1 배치 구성

**그룹핑**: ① 모드 단위 → ② 모드 내 키 접두사/원본 파일 단위 정렬 후 순차 절단(`#LOC_CRP_Food_*`가 한 배치에 모이면 문맥 공유로 일관성 상승) → ③ 긴 값 분리(값 길이 >400자는 별도 큐, 배치당 3개 이하).

**이중 상한**: payload 입력 토큰 ≤2,000 그리고 키 개수 ≤40. 출력 토큰이 진짜 제약. 한국어 출력 추정: `한국어 문자수 ≈ 영어 문자수 × 0.9`, `한국어 토큰 ≈ 문자수 / 1.4`.

**페이로드 — 인덱스 라운드트립**:

```json
[{"i": 1, "k": "#autoLOC_500100", "en": "Stage <<1>> ready for separation."}]
```
```json
[{"i": 1, "ko": "<<1>>단 분리 준비 완료."}]
```

- 키(`k`)는 보낸다 — `_PART_TITLE`/`_DESC`/`_TOOLTIP` 접미사가 문체·길이 제약을 결정하는 신호.
- 매칭은 **`i`로만** — 응답에 키 문자열을 요구하면 모델이 키를 변형·절단할 위험 + 출력 토큰 낭비. (기존 구현은 `item["key"]` 매칭이라 키가 한 글자만 틀려도 조용히 유실)

### 2.2 구조화 출력

```python
response_schema = {"type": "ARRAY", "items": {"type": "OBJECT",
  "properties": {"i": {"type": "INTEGER"}, "ko": {"type": "STRING"}},
  "required": ["i", "ko"]}}
```

`_strip_markdown_fences`와 JSON 파싱 폴백 경로가 통째로 불필요. 생성 파라미터: `temperature=0.2`, `max_output_tokens = 예측 출력 × 2.5`, `thinking_budget=0`.

### 2.3 병렬·레이트리밋

- 기본 동시 8 (기존 10 → 하향; 무료 티어 RPM 고려).
- 공유 토큰버킷 리미터: 요청 전 토큰 예약 (세마포어만으론 RPM/TPM 못 지킴).
- 429: `retry-after`/`RetryInfo` 우선, 없으면 지수 백오프+지터. 429 연속 3회 시 동시성 절반 감축, 60초 무사고 시 1씩 복구(AIMD). 백오프 대기는 세마포어를 잡은 채로(의도적 — 전체 압력 감소).

### 2.4 실패 처리 — 조용한 유실 금지

기존 `translate_batch`는 태스크 예외를 삼켜 실패 키가 결과에서 사라진다. 새 계약:

```python
@dataclass
class BatchOutcome:
    batch_id: str
    ok: dict[str, str]        # key -> 한국어
    failed: dict[str, str]    # key -> 실패 사유
    usage: Usage
```

`translate_job()`은 `TranslationReport(ok, needs_review, failed, usage, cost)`를 반환하고 **모든 입력 키는 반드시 세 버킷 중 하나에 속한다**(불변식, 단위 테스트로 고정). 실패는 정상 결과 — 영어 폴백이 엔진 차원에서 안전하므로.

### 2.5 중단-재개 상태 저장

```
<data_dir>/jobs/<jobId>/
├── manifest.json   # 모드ID, 소스 해시, 모델명/단가, 배치 계획(batch_id -> keys)
├── results.jsonl   # 배치 완료마다 1줄 append: {batch_id, items:[{k,ko}], usage}
├── failures.jsonl  # {batch_id, key, attempt, reason}
└── review.jsonl    # 검증 최종 실패 → 검수 큐
```

- 배치 계획을 미리 확정해 매니페스트에 저장 — 재개 시 재분할하지 않으므로 부분 결과와 항상 정합.
- 재개: 완료 `batch_id` 집합 제외 실행. 마지막 줄이 깨졌으면 그 줄만 폐기.
- 소스 해시 불일치 시 재개 거부 → "모드가 업데이트됨, 새 잡 시작".
- 일시정지 = 신규 디스패치 중단 + 진행 중 완료 대기. 취소 = 진행 중 취소(완료분 보존).
- 누적 비용은 `results.jsonl`의 usage 합계로 재계산 — 프로세스 재시작에도 비용 표시 유지.

## 3. 프롬프트 설계

### 3.1 3층 구조

```
[A] 시스템 프롬프트 (전 요청 동일, 캐시 대상) — 역할 + 토큰 보존 규칙 + 문체 정책 + few-shot
[B] 모드 컨텍스트 (모드당 동일, 캐시 대상) — 모드명/설명 1~3줄 + 배치에 등장하는 용어집 엔트리
[C] 페이로드 (배치마다 변경) — JSON 배열
```

캐시 히트를 위해 A/B는 바이트 단위 안정 — 타임스탬프·잡 ID·키 개수 금지.

### 3.2 시스템 프롬프트 초안

```
당신은 Kerbal Space Program 로컬라이제이션 전문 번역가입니다.
영어 원문을 한국어로 번역합니다. 입력은 JSON 배열이고, 각 항목의 "en"을
번역해 {"i": <같은 인덱스>, "ko": "<번역문>"} 형태로 반환합니다.
모든 항목을 빠짐없이, 입력과 같은 개수로 반환하십시오.

## 전제
이 목록은 이미 "번역해야 하는 키"만 선별된 결과입니다. 번역을 건너뛰지
마십시오. 다만 아래 규칙에 따라 일부 어휘는 영어로 유지합니다.

## 절대 보존 규칙 (위반 시 게임이 깨집니다)
1. `<<1>>`, `<<2>>` … 치환 토큰: 개수와 번호를 그대로 유지. 위치는 한국어
   어순에 맞게 옮겨도 됩니다. 새로 만들거나 지우지 마십시오.
2. `^N`, `^F`, `^M` 등 캐럿 마커: 바로 앞 단어에 붙은 채로 유지합니다.
   (Lingoona 문법 마커입니다. `Kerbal^N` → `커발^N`)
3. `\n` (역슬래시+n): 개수를 그대로 유지합니다. 실제 줄바꿈으로 바꾸지 마십시오.
4. `｢` `｣` (전각 괄호): 그대로 유지. 이것은 이스케이프된 중괄호입니다.
   번역문에 맨 중괄호 `{` `}` 를 절대 넣지 마십시오.
5. 리치텍스트 태그 <b> </b> <i> </i> <color=#RRGGBB> </color> <sprite=…>:
   태그와 속성값을 그대로 유지하고 짝을 맞춥니다.
6. printf 형식 지정자 `%s %d %f %.1f`, .NET 형식 `{0}` `{1}`: 개수와 순서 유지.

## 어휘 정책
- 용어집에 있는 항목은 지정된 번역을 정확히 사용합니다.
- 용어집에서 "영어 유지"로 표시된 항목은 번역하지 않고 그대로 둡니다.
- 용어집에 없는 고유명사(모드명, 파트 코드명, 인명, 회사명, 행성/위성명)는
  영어를 유지합니다. 억지로 음차하지 마십시오.
- 단위와 기호는 영어/기호를 유지합니다: m/s, km, kN, t, Δv, EC/s, %, °.
  숫자 표기는 바꾸지 마십시오.
- 키보드 키 이름(Tab, Shift, Ctrl, Alt, Esc)과 제품·기술명(Track IR,
  ModuleManager)은 영어를 유지합니다.

## 문체
- 기본은 '합니다체'(하십시오체) 존댓말입니다. 반말·해요체를 쓰지 마십시오.
- 키 이름으로 문체를 결정합니다:
  - `_TITLE`, `_NAME`, `_DISPLAYNAME`, 버튼/레이블 → 명사형으로 끝냅니다.
    조사·서술어를 붙이지 마십시오. ("연료 탱크", "발사" — "발사합니다" 아님)
  - `_DESC`, `_DESCRIPTION`, `_TOOLTIP`, 안내문 → 완결된 문장, "~합니다 / ~하십시오".
  - 오류·경고 메시지 → "~할 수 없습니다", "~가 필요합니다".
- UI 레이블은 원문보다 눈에 띄게 길어지지 않게 간결히 씁니다.
- KSP 특유의 가벼운 유머는 살리되, 억지 의역은 하지 않습니다.

## 출력
JSON 배열만 반환합니다. 설명, 주석, 마크다운을 붙이지 마십시오.
```

### 3.3 few-shot — 포함한다

토큰 보존은 서술 규칙보다 예시로 훨씬 잘 학습된다. ~400 토큰, 캐시 대상. 유형별 1개씩 8개 고정: ① `<<n>>` 어순 재배치 ② `^N` 붙은 단어 ③ `\n` 다중 ④ 태그 중첩 ⑤ `_TITLE` 명사형 ⑥ `_DESC` 합니다체 ⑦ 고유명사 영어 유지 ⑧ 단위·숫자 혼재.

부정 예시(하지 말 것)는 넣지 않는다 — 소형 모델에서 그 패턴을 유도하는 역효과.

### 3.4 용어집 주입 — 관련 항목만

1. 배치의 모든 `en` 값 연결 텍스트에 코어+모드 용어집 `term`/`aliases`를 대소문자 무시 + 단어 경계 매칭
2. 매칭된 엔트리만 [B]에 삽입, 상한 60개(초과 시 출현 빈도순)
3. 최소 토큰 형식:

```
## 용어집 (이 배치에 해당하는 항목만)
delta-v => 델타-V
apoapsis => 원점
Karbonite => (영어 유지)
```

### 3.5 기존 SYSTEM_PROMPT 대비 변경점

| 기존 | 변경 | 이유 |
|---|---|---|
| `"^N (%.0f, %s, etc.)"` 한 줄 | `^N`(Lingoona 마커)과 printf 지정자 분리 규칙화 | 완전히 다른 것을 묶어 모델이 혼동. `^N`은 단어에 붙는 접미사 |
| 프롬프트가 영어 | 한국어로 작성 | 출력 언어와 지시 언어 일치 시 문체 준수율 상승 |
| 용어 6종 하드코딩 | 용어집 데이터로 이관 + 선별 주입 | 모드별 용어집이 1급 개념. 프롬프트 하드코딩은 DB와 이원화 |
| "Keep proper nouns in English"만 | 단위/키보드 키/제품명 명시 + 음차 금지 | 영어 유지 대상 상당수가 고유명사가 아니라 단위·포맷·키 이름 |
| 존댓말 1줄 | 키 접미사 기반 문체 결정 규칙표 | 파트 이름이 "연료 탱크입니다"가 되는 전형적 실패 방지 |
| `｢｣` 언급 없음 | 규칙 4로 명시 | ConfigNode 파스 트리 파괴 = 프리즈 원인 후보 1순위 |
| few-shot 없음 | 8개 고정 | 토큰 보존 정확도 |

## 4. 검증 루프

### 4.1 기계 검증 (키 단위)

| # | 검사 | 등급 |
|---|---|---|
| 1 | 빈 값 / 공백만 | ERROR |
| 2 | `<<n>>` 토큰 멀티셋 일치(번호별 개수) | ERROR |
| 3 | `\^[A-Za-z]` 캐럿 마커 개수·문자 일치 | ERROR |
| 4 | `\n` 리터럴 개수 일치 | ERROR |
| 5 | 리치텍스트 태그 종류·속성값 멀티셋 일치 + 짝 균형 | ERROR |
| 6 | printf / `{n}` 멀티셋 일치 | ERROR |
| 7 | 맨 `{` `}` 등장 / `｢｣` 개수 불일치 | ERROR |
| 8 | 원문과 완전 동일(원문에 한글 없고 라틴 문자 존재) | WARN |
| 9 | ja 화이트리스트(단위/포맷류) 위반: 자동 영어 유지 키에 한글 등장 | ERROR |
| 10 | 길이비(한국어/영어 문자수) `[0.25, 2.0]` 밖 | WARN |
| 11 | 용어집 위반 | WARN (`keep` 위반은 ERROR) |

**배치 단위**: 반환 항목 수 ≠ 요청 수 또는 `i` 집합 불일치 → 누락 키 전체 ERROR / 중복 `i` → 후자 폐기 + WARN.

**팩 단위(적용 직전)**: 생성된 cfg의 ConfigNode 라운드트립 재파싱(실패 시 팩 전체 차단), 팩 간 중복 태그 검출, BOM 없는 UTF-8 확인.

### 4.2 자동 재번역 — 키당 최대 2회 (총 3회 시도)

| 시도 | 배치 크기 | 모델 | 추가 컨텍스트 |
|---|---|---|---|
| 1 | ≤40 | Flash-Lite | 없음 |
| 2 | ≤8 (실패 키만 재묶음) | Flash-Lite | 위반 내용 항목별 주입 |
| 3 | 1 | 3 Flash (에스컬레이션) | 위반 내용 + 이전 출력 |

피드백 주입:
```json
{"i": 1, "k": "#autoLOC_500100", "en": "Stage <<1>> ready.",
 "prev": "단 준비 완료.",
 "fix": "치환 토큰 <<1>> 이 누락되었습니다. 반드시 포함하십시오."}
```

**시도 3도 실패 → `review.jsonl`로 이동, 해당 키는 팩에서 제외.** 키가 없으면 엔진이 en-us로 자동 폴백 — **깨진 번역보다 영어가 항상 낫다**가 안전 기본값.

**서킷 브레이커**: 한 모드에서 시도 1 ERROR 비율 30% 초과 시 잡 일시정지 + 경고. 잘못된 설정으로 60,000키를 태우는 사고 방지.

비용 영향: 실패율 5% 가정 시 재번역 비용 ≈ 전체의 6% (§1.4의 ×1.15에 반영).

### 4.3 검수 큐

`review.jsonl`: `{key, en, ko_candidates:[시도별 출력], violations:[...], mask_status, glossary_hits}`. 에디터에서 [원문 | 번역 후보 | 위반 목록 | 상태] 표시, 사용자 수정 시 같은 검증기를 즉시 재실행해 통과 여부 인라인 표시 → 통과 시 `검수됨` 승격.

## 5. 용어집 자동 초안 생성 파이프라인

휴리스틱으로 후보를 좁히고 LLM은 분류만 시킨다.

### 5.1 후보 추출 (결정적, LLM 없음)

값에서 `<<n>>`·태그·형식 지정자·숫자 제거 후:

**후보 신호** — 문장 첫 단어가 아닌 대문자 시작 단어 / 연속 Title Case 구(≤4단어) / CamelCase·PascalCase / 키 이름 조각(`#LOC_CRP_Karbonite_DisplayName` → `Karbonite`, 신뢰도 최상) / 서로 다른 값 3개 이상 등장(임계값 `max(3, 총키수/200)`).

**필터** — 불용어·1~2글자 제외, 코어/확정 모드 용어집 기존 항목 제외.

**공식 번역 대조 (핵심 신호)** — 모드가 zh-cn/ja를 동봉했다면 후보 문자열이 공식 번역문에도 라틴 문자로 그대로 남아 있는지 확인. 남아 있으면 `policy: keep`으로 자동 확정하고 LLM에 보내지 않는다. 무료로 얻는 가장 정확한 정답 소스.

상위 150개만 다음 단계로 (출현 빈도 × 신호 가중치).

### 5.2 LLM 분류 (요청 1~2회, ~$0.01)

각 후보에 실제 사용 예 최대 3개(각 120자 이내) 동봉 — 사용 예가 있어야 `Bay`가 "화물칸"인지 "만(灣)"인지 판별 가능.

```
KSP 모드 "<모드명>"의 로컬라이제이션에서 추출한 용어 후보입니다.
각 후보를 아래 정책 중 하나로 분류하고, 번역이 필요하면 한국어를 제시하십시오.

- keep      : 고유명사·식별자. 영어 유지 (모드명, 파트 코드명, 제품명,
              창작 자원명, 인명, 행성/위성명)
- translate : 일반 기술 용어·명사. 모드 전체에서 일관되게 쓸 한국어 번역
- translit  : 음차가 관례인 고유명사 (Kerbal → 커발)
- noise     : 용어가 아님 (일반 영단어, 추출 오류, 문장 조각)

한국어 게임 번역 관례를 따르십시오. 확신이 없으면 keep을 고르십시오.
근거는 한 줄로 짧게 씁니다.
```

스키마: `{"term": str, "policy": "keep|translate|translit|noise", "ko": str|null, "confidence": "high|medium|low", "why": str}`. `noise` 자동 폐기.

### 5.3 사용자 확정

[용어 | 정책 | 한국어 | 근거 | 출현 횟수 | 사용 예] 테이블, 출현 횟수 내림차순, `confidence: low` 강조. 일괄 승인/개별 수정/삭제. **확정된 엔트리만** 번역 프롬프트에 주입.

### 5.4 스키마

```json
{"version": 1, "entries": [
  {"term": "Karbonite", "policy": "keep", "ko": null, "aliases": ["karbonite"],
   "notes": "공식 zh-cn/ja 번역에서 영어 유지 확인",
   "source": "official-mask", "confirmed": true},
  {"term": "delta-v", "policy": "translate", "ko": "델타-V",
   "aliases": ["deltaV", "Δv", "dV"], "source": "core", "confirmed": true}
]}
```

`aliases`는 매칭에만 쓰고 프롬프트엔 출력하지 않는다. CI는 용어집 위반을 경고로만 처리.

## 6. 기존 구현 대비 변경 요약 (구현 계획 입력)

`translator.py`는 사실상 재작성 대상.

**발견한 버그/결함:**
1. `translate_batch`가 태스크 예외를 삼켜 실패 키가 조용히 사라짐
2. 배치 응답을 `item["key"]`로 매칭 → 모델이 키를 한 글자만 바꿔도 유실. 인덱스 매칭으로 교체
3. 배치 응답 항목 수 부족이 검출되지 않음(개수 검증 부재)
4. `classifier._should_skip`의 `key.endswith("^N")` — `^N`은 값에 붙는 Lingoona 마커이지 키 접미사가 아님
5. `cost.py` 단가가 모듈 상수 → 모델 교체 시 비용 표시 오류
6. `estimate_tokens`(4자=1토큰)는 영어 전용 근사 — 한국어 출력 예측에 부적합
7. `_strip_markdown_fences` + JSON 파싱 폴백 → 구조화 출력 도입 시 전부 삭제

**신규 모듈**: `providers/`(프로토콜+Gemini) · `batching.py` · `prompt.py` · `validate.py` · `jobstore.py` · `glossary.py` · `limiter.py`

**검증 방법(성공 기준):**
- 검증기 단위 테스트: 규칙별 통과/실패 쌍. **Dobie 번역 dictionary.cfg 12,041줄을 골든 입력으로** — 사람이 검증한 번역이 우리 검증기를 통과하지 못하면 검증기가 틀린 것
- 배치 계획: 임의 입력에 대해 `모든 입력 키 = 모든 배치 키의 합집합`, 중복 없음
- 재개: 잡을 임의 지점에서 죽이고 재개 → 무중단 실행과 결과 동일
- E2E: 소형 모드 1개(≤200키)를 실제 API로 번역 → 검증 통과율·비용 실측 → §1.4 가정 보정
